Three shapes, one process per shape, work fixed per shape so ops and checksum must be identical across legs (summariser asserts both; PASS): kv_append - 32 sequences each grown by 64 realloc appends of 4 KiB to 256 KiB, every step touched (the KV append path); kv_blocks - a resident pool of 256 x 64 KiB blocks held live (the cached prefix) while 4 KiB per-token blocks churn through a 128-slot FIFO ring, 2048 churn allocs per pass (ops count = churn allocs; elapsed includes the one-time resident build, identical for every leg); kv_mixed - resident 128 x 256 KiB plus 16 sequences append-grown 32 x 8 KiB plus eviction rotation (free oldest 32 residents, allocate fresh), the serving mix.
