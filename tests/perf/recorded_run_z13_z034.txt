  EVERY class. There is no per-block header to diet.
  Live blocks carry no metadata at all; freed blocks
  thread the span free list in-band in their own first
  8 bytes (a cost paid only by dead memory).

  per block in the table above: 0.384 B/block at 16 B

  Span efficiency (object bytes / page): 97.66% at
  16/32/80/160 B, worst 75.00% at 1024 B (tail waste

=== THE REAL FINDING (named follow-up, not adopted here) ===
The churn256 win is NOT a metadata-space effect. It is
the free path: production find_span_live_locked proves
liveness by WALKING the span's free list - O(carve_count)
per free, up to 250 nodes at 16 B - while the trial's
bitmap answers in O(1). Batch free/realloc patterns pay
the walk on every free (prod churn256 232.94 ns/op at
16 B vs churn1 26.78). The promising hybrid - a per-span
liveness BITMAP as an index only, keeping the in-band
LIFO free list for reuse order - is named here as
follow-up evidence for Z-030's remote-free work and any
future free-path slice. It is NOT built in Z-034:
adopting it needs its own slice, its own gate run, and
its own verdict. The churn1 regression (+9-10%) is the
bitmap scan + side-page touch on the single-block road;
the control class (128 B, untrialled) moved only
+3.76% / +1.35%, inside the noise band.
