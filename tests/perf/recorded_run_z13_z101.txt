=== METHOD ===
One probe source, two legs (Z-004 protocol via run_z101.sh: one warm-up process per leg discarded, then 3 recorded processes per leg, alternating): mimir (full accounting) and glibc (-DUSE_GLIBC, identical shapes, wall-time comparator only). Per process, in order:
  CAL calibration: one thread runs the exact Z-042 churn shape and captures its own TLS snapshot before exit (cached_blocks=46, cached_bytes=14912, identical in every rep, identical to Z-042's calibration): the exit destructor must return exactly those 46 blocks.
  CMB the combined storm - the three storms OVERLAP in one window: 16 churn looper threads run short-lived alloc/touch/verify/free cycles continuously; 16 ring workers run fixed cross-free rounds (16 x 20 x 256 blocks of 64 B = 81,920 remote frees, every block pattern-verified by its freer); while both run, main performs 256 fork+exec(/bin/true) children (the Z-044 E2 proven shape - the child only execs). Churn loopers run for the whole fork window (stop flag set only after the last child is reaped). Exit drains at the post-combined snapshot: 33 = 1 calibration + 16 loopers + 16 ring workers, exactly.
  STM thread-churn at Z-042 scale: 10,000 one-shot churn threads in waves of 32, 35 allocations each (8 in each of classes 16/64/256/1024, one 2048 B large, two held blocks handed to main). Asserted exactly as Z-042: exit drains +10,000, exit-drained blocks +460,000 (= 10,000 x 46), counters settled after a 100 ms quiesce, live exactly baseline + 20,000 held; main then verifies and frees the held blocks and live returns to baseline.
  RNG free-storm at Z-043 S1 scale: 32 threads ring cross-free, 3 rounds x 2,048 blocks of 64 B = 196,608 remote frees, pattern-verified by the freer before the free.
  FRK fork storm, supported shapes only (Z-044): 16 quiescent fork+alloc children (parent single-threaded at the fork instant; child allocates/verifies/frees and _exit(0/42)) + 500 sequential fork+exec(/bin/true). The fork-while-busy ALLOC shape stays measured-unsupported per Z-044 B1 and is not exercised as a correctness leg; under load this battery forks only to exec (CMB).
  TRIM byte-exact close (Z-042): main drains its own TLS cache, mimir_core_trim_retained() releases exactly the pre-trim retained spans (9 spans / 36,864 B in every rep), the Z-048 pool is released too, and bytes_mapped returns to the pristine S0 figure (0) to the byte - the leak arbiter for the whole battery.

=== ACCOUNTING FINDING (probe defect, fixed in-slice; no production defect) ===
The first trial run FAILED one identity in every snapshot: bytes_mapped exceeded live_span_bytes + live_mapping_bytes by 8,192 B early and 131,072 B after the churn storm. Root cause, proven from source before any fix: the two-term identity is Z-042's and predates the Z-048 mapping pool - on the near-final core Q-MAPPED is DEFINED as live span bytes + live mapping bytes + pooled mapping bytes ("a pooled mapping is still mapped", src/core/mimir_core.c Q-MAPPED comment; snapshot composition at the mimir_core_stats_snapshot site). The probe now reads the pool through its own Z-048 query pair (tests/core/mimir_pool_z048.h) and asserts the three-term identity at every snapshot; it holds exactly in all recorded reps (pool_bytes per rep-1 snapshots annexed below: 0 at S0, 8,192 after calibration, 114,688 after the churn storm, 0 after trim). This was a stale comparator in this slice's own probe, not an allocator bug: every other identity (cached == retained, retained == empty spans x 4096, metadata walk, byte-exact trim close) held even in the failed trial, and the final mapped figure returns to 0 with pool_bytes 0. Recorded per the never-leave-a-bug rule: the defect was in the slice's harness, fixed inside the slice's scope, and the fix is part of the banked probe source.
