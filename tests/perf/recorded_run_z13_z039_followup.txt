2. WHAT WAS BUILT - geometry B behind MIMIR_LOCK_SHARD
================================================================
Form of adoption, the Z-037/Z-034 pattern: a flag-gated
prototype. The production default remains the banked central
lock; a flag-off build is byte-identical to the seat's
(zero-cost proof in section 3). Making sharding the default
is a later adoption decision, not this slice's.

Design, following the Z-039 part-1 paper design:
  - K = 4 shard locks (L6, src/platform): shard map by class
    GROUP - class 0 (16 B) -> shard 0, class 1 (32 B) ->
    shard 1, classes 2..3 (48, 64 B) -> shard 2, classes
    4..19 (80..1024 B) -> shard 3. Each shard mutex is
    cache-line padded (Z-016 rule); per-shard acquisition
    counters and a lock-order audit (thread-local held-mask;
    taking a shard while a higher-or-equal shard is held is
    counted as a violation, never silently allowed) live in
    the platform layer.
  - Per-shard span lists: the span registry head becomes
    mimir_shard_span_head[shard] selected by a thread-local
    hint naming the shard of the class being served.
  - Fixed global lock order: shards ascending, then the
    retained global lock LAST (it guards the mapping
    registry). Banked global sections (large path, stats,
    metadata check, retained snapshot, drain/trim, tune,
    TLS drain, destructor) take ALL shards ascending + the
    global lock by macro superset, so their bodies are
    unchanged and the order is honoured by construction.
  - Hot paths take exactly ONE shard: TLS refill miss, TLS
    full-bin drain, pending-full direct accounting,
    cross-thread free of a span object (searches the shard
    lists ascending, keeps only the found span's shard).
    Two-class operations (realloc) run under the global set,
    the superset course the paper design allows.
  - Shared counters that shard sections update concurrently
    (live spans/bytes/objects, stats byte counters) are
    _Atomic in a shard build only; the peak sampler is a
    CAS-max. The per-span TLS tally table is replicated per
    shard, selected by the span's own class.
  - Combinations refused with #error, Z-037 precedent:
    MIMIR_LOCK_SHARD with MIMIR_DEBUG, MIMIR_ARENA_CCD,
    MIMIR_OOL_META or MIMIR_LOCK_HIST (each combination is
    unmeasured surface; the refusal was exercised in this
    session - SHARD+DEBUG build fails at the #error).
