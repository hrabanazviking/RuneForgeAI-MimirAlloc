S2. Method (Z-004 protocol)
Probe tests/perf/probe_z069.c: one process per (leg, class)
cell; W blocks held in a probe array; one timed cycle =
acquire all W (mimir_malloc), touch byte 0, release all W in
order (mimir_free); ns/op is per alloc+free pair. Warm-up
cycle untimed with a pairwise-distinctness proof on all W
pointers (exit 5 on failure). Checksum is a deterministic
function of (block index, cycle), identical across legs by
construction; the summariser refuses (INVALID) any class
whose legs disagree on checksum or any nonzero canary
fault count. Runner tests/perf/run_z069.sh: every process
pinned taskset -c 5, 3 warm-up processes per leg discarded,
5 measured processes per cell, legs interleaved round-robin
per repetition round, headline = median
(tests/perf/summarize_z069.py). Legs: base (production, no
canary), base_dup (identical duplicate; agreement control,
bound 5%), can16 (16 B canary fill at handout + verify at
free per block), can32 (32 B, same shape). The canary legs
place the pattern (0xA5, the J-004 byte) in the last N
bytes of the block extent -- the in-slack / stride-tail
position a production tail canary occupies -- so the
fill+verify instruction cost is measured on the real
alloc/free cycle of this tree. Cells: representatives
16/32/64 (G1), 128/256 (G2), 512/1024 (G3), 8192/65536
(G4); W = 4096 blocks (footprint <= 4 MiB) for classes
<= 1024, 256 blocks for the large classes; 4 timed rounds
per process. Two full sweeps were run; both are preserved
(hidden_files/z069_raw.txt, z069_raw2.txt) and both give
identical group verdicts (S5). Sweep 1 is the headline;
sweep 2 is the confirmation.

Grading rule (stated in summarize_z069.py, applied
mechanically): for one (form, class) --
  ADOPT-CANDIDATE: time delta <= max(1.0 ns/op, 2% of base)
    AND stride capacity loss <= 10%
  REJECT: time delta > max(3.0 ns/op, 5% of base) OR
    capacity loss > 10%
  else MARGINAL.
Group verdict = the worst verdict among its measured
representative classes (a group adopts only if every
representative can pay the price).

PROBE DEFECT FOUND AND FIXED IN-SLICE: the first draft's
can32 leg wrote its 32 B at offset 0 of the block; on the
16 B class that is a 16 B overflow past the extent, and
the first sweep segfaulted after 15 rows (raw preserved as
hidden_files/z069_raw_attempt1_segfault.txt). The fault
was the probe's, not the allocator's: no production code
was running anything but ordinary malloc/free. Fixed by
chunk-wrapping the fill+verify inside the extent when the
class is smaller than the canary (full N bytes of work,
zero bytes outside the block); the fixed probe re-ran both

Nominal bytes/block: +16 (tail16) or +32 (full32) of
stride. The capacity loss is the honest form of that
price: at tiny classes the stride growth eats whole slots
per page; at 512/1024 the page slack absorbs the growth
entirely (floor effects: 4000/528 and 4000/544 both floor
to 7; 4000/1056 and 4000/1088 both floor to 3).
Nuance, recorded not hidden: these are worst-case
full-class requests. A request with >= 16 B of slack
inside its class (request <= class-16) can carry a tail
canary in-slack at ZERO byte cost in any group; the
verdicts below govern the always-on stride forms, which
must price the worst case.

S5. Verdicts per class group
G1 tiny (classes 16-64): REJECT tail16, REJECT full32.
  Time is noise (+0.54%..+0.96% tail16) but bytes are
  not: capacity loss 19.35%-50.00% (tail16) and
  33.87%-66.80% (full32). An always-on canary here pays
  up to two-thirds of the arena for guard bytes.
G2 small (classes 80-256): REJECT tail16, REJECT full32.
  Governed by class 128 (loss 12.90% / 19.35% > 10%).
  Class 256 alone would adopt tail16 (loss 6.67%, time
  +0.81%) and reject full32 (13.33%); a group verdict
  cannot adopt on its best class and bill its worst.
G3 medium (classes 320-1024): ADOPT-CANDIDATE tail16,
  ADOPT-CANDIDATE full32. Representatives 512 and 1024:
  capacity loss 0.00% for both forms (page slack absorbs
  the stride), time +0.01%..+0.46% (tail16) and
  +0.06%..+0.55% (full32) in sweep 1; sweep 2 confirms
  (+0.43%/+0.97% at 1024, the noisiest cell, still inside
  the 2% adopt band). This is the one group where the
  price is noise on BOTH axes.
G4 large (>1024, descriptor/mapping path): REJECT
  tail16, REJECT full32. The measured delta (+329 ns /
  +14.46% at 8192; +669 ns / +29.40% at 65536, sweep 2
  +352/+695 ns) is NOT fill+verify instruction cost --
  can16 and can32 cost the same within noise, which no
  instruction-count story explains. Mechanism: a tail
  canary on a fresh mapping must be written at handout,
  which faults in the mapping's tail page that the
  workload (and typical callers) may never touch; the
  base leg touches one page per block, the canary legs
  touch one more. A canary that costs a page fault per
  fresh large block is not noise at any size. (J-004
  scoped the mapping path out of its red zones for its
  own reasons, INC-J004-01; the economics here agree.)
Standing of the existing canary: the J-004 debug red
zones (16 B pre + 16 B post, MIMIR_DEBUG builds only)
are untouched by these verdicts -- debug builds pay for
detection with capacity by design. These verdicts govern
PRODUCTION always-on adoption only.

S6. Adoption record and follow-on
Adopted as verdict: G3 tail16/full32 (either form; the
choice between them is an implementation-slice decision
-- full32 buys the pre-zone, the metadata-adjacent guard,
at the same measured price on this group).
NOT implemented in this slice: a production stride change
for the 320-1024 classes touches span carve geometry,
the TLS cache batching over those classes, and the J-002
accounting of allocated bytes; by campaign precedent it
lands as its own flag-gated implementation slice
(MIMIR_CANARY stride variant, G3 classes only) with its
own gate run and detection proofs. Recorded here and in
the team's CAMPAIGN_STATE.md as the named next work if
the keeper queues it; Z-069's own gate (cost table +
verdicts) does not require it.
Rejected groups need no follow-on: G1/G2 stay canary-free
in production (in-slack tail canaries for slack-rich
requests remain available to a future design at zero
byte cost, S4 nuance); G4 stays as J-004 scoped it.
