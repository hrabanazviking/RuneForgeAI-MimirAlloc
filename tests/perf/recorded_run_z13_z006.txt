=== METHODOLOGY ===
Harness: tests/perf/bench_k002.c UNMODIFIED (sha256 30dd0d9a8da12b03aa511fd35a4a098cf593b79c0e9ad352026ecb11eacc7d37 - identical to the Z-003 recorded hash). The RSS leg is built AROUND it: tests/perf/probe_z006.c includes bench_k002.c with its main() renamed away and adds no workload code of its own - the workload functions, size tables, op definition (one allocation plus its matching free) and checksums are exactly the banked Z-003 ones.
Why a probe: bench_k002 runs each workload flat-out and frees as it goes, so an external sampler cannot hit defined memory states. The probe runs ONE workload per process (argv-selected) and stops at DEFINED PHASES, printing a PHASE marker and blocking on stdin while the runner reads /proc/<pid>/smaps_rollup:
  START          process up, before any workload call
  WARM           after the 1/10-scale warm-up pass (exactly the bench_k002 warm-up)
  STEADY         after half of the R timed passes (R per workload: small_churn 20, mixed_batch 5, large_batch 20, mixed_lifecycle 10 - the Z-005 reps)
  PEAK           the characteristic live set of the workload allocated and fully memset (every page touched, so RSS is real, not just reserved); live bytes printed first and identical across legs (proof both legs held the same set)
  AFTER_FREE     odd slots of the live set freed
  AFTER_FREE_ALL every held block freed (the retention point: what the allocator still holds resident with nothing live)
PEAK live sets (the characteristic set of each workload): small_churn 8192 blocks cycling small_sizes (851968 B - the bench live set is a single block, so a defined accumulation is used and stated here, per the probe header); mixed_batch 256 blocks, one full bench batch (79872 B); large_batch 32 blocks, one full bench batch (7024640 B); mixed_lifecycle 512 blocks, one full bench round set (703936 B).
Sampling: at each phase the runner (tests/perf/run_rss_z006.py) reads smaps_rollup 3 times, 20 ms apart, and records the median per field; the table below is the median across 5 measured processes per leg per workload. Processes pinned with taskset to CPU 2 (Z-004 protocol). Legs alternate process by process (glibc, mimiralloc) per workload, house pattern. Fields are the smaps_rollup totals in kB: Rss, Pss, Pss_Anon, Pss_File, Private_Clean, Private_Dirty, Shared_Clean, Shared_Dirty, Swap. Swap is 0 in every row - no row is swap-contaminated.
Grading: verdicts at PEAK and AFTER_FREE_ALL on median Pss and Pss_Anon, mimiralloc vs glibc, 5% noise band = TIE (Z-004 protocol s.7); drift check on PEAK Pss, first vs second half of processes, 8% band (s.8) - no DRIFT-REJECT. Summariser: tests/perf/summarize_z006.py.
