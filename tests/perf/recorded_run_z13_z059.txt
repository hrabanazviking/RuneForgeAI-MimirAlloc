=== METHOD ===
Roadmap gate: "First-fit vs best-fit (vs current policy) measured on the fragmentation oracle before any change is adopted. Gate: policy comparison table + ledger decision on adoption." The oracle is Z-055's (banked recorded_run_z13_z055.txt): the F-series fragmented state on this host. The three policies differ only in which span serves a small allocation when several spans of the class can serve; the choice lives in exactly two mirrored sites, small_alloc_locked and tls_take_one_locked, and the trial implements both variants in both sites behind the flags (placement_select_locked): FIRSTFIT ignores the class's active span and takes the first can-serve span in list order; BESTFIT takes the can-serve span with the fewest servable slots (capacity - live_count - TLS-binned tally, from the TLS invariant free-list nodes + live_count + tally == carve_count, saturated at 0; ties by list order). Within a span nothing changes (LIFO free-list pop, else carve). A variant's chosen span becomes the class's active span, exactly as the banked scan path sets it, so no state writeback differs between policies.
Leg A (control) is Z-055's standard fragmented state verbatim: larges 20000/40000 kept live; classes 64/256/1024 filled to 3 x capacity; odd indices freed; quiesce; F-3 / tails / R-EXT / R-INT from measured per-class deltas (I-002 formula). Filling fresh spans gives a policy no hole to choose, so every leg A number must reproduce Z-055 exactly in every build - the probe asserts F-3 == 32064, tails == 3360, Q-MAPPED == 122880, bearing == 3 and live == 93/23/5 per class.
Leg B (decision leg), per class 64 and 256 from a clean state: fill 3 x capacity, quiesce, group blocks by span (span == one 4096 B page on this host, so a pointer's page is its span - the leg B claim is restricted to these verified 1-page-span classes), free unevenly by group rank in page order (rank 0: all but 1; rank 1: half; rank 2: all but 2), quiesce, then 24 follow-on allocations of the class (24 > the TLS refill batch of 16, single thread, so a bin batch cannot mask the policy). Metrics: distinct spans touched by the follow-ons; new spans published in the follow-on phase; P2 = spans empty at quiesce after freeing ALL original blocks with the follow-ons still live (retained-empty + sweep-released during that free). The decision rule was pre-registered in probe_z059.c before any run and is applied exactly by the summariser; D-009 records the outcome.
Team structure: team-04 lead + 6 Mythic Engineering sub-agent reviewers mustered in parallel (design, implementation, gate verification, battery reconciliation, measurement, risk/commit-scope) - no 429s. Their material corrections were folded in BEFORE the runs: follow-on volume raised above the TLS batch; three runs per policy with bit-identical counters required; per-policy object hashes recorded; the best-fit key saturated against tally skew; first-fit added as a control clause (clause e) so an active-pointer effect cannot be misread as a fit effect; gate demanded on the final default tree with counts read from the log.

=== READING - PLACEMENT VERDICT ON THIS HOST (roadmap gate) ===
Gate: "policy comparison table + ledger decision on adoption" - MET. The table is the SUMMARY above; the decision is D-009 in docs/DECISION_LEDGER.md: NO ADOPTION. The current policy (active span first, then first-fit scan, then a fresh span) stays as the production default; neither trial policy is adopted in any form by this slice, and the trial code remains available behind MIMIR_PLACEMENT_FIRSTFIT / MIMIR_PLACEMENT_BESTFIT for any future re-trial.
Control (leg A): all three builds reproduce Z-055's fragmented state EXACTLY - F-3 32064, tails 3360, R-EXT 0.260937, R-INT 0.091146, Q-MAPPED 122880, Q-RETAINED 16384, per-class acquired/released/retained/bearing/live identical to the banked Z-055 record (64: 4/0/1/3/93; 256: 4/0/1/3/23; 1024: 6/1/2/3/5). The trial harness and the flag wiring are therefore proven against the oracle before any leg B number is read: a leg A difference in any build would have voided the trial, and there is none.
Decision leg (leg B): at class 64 the three policies are indistinguishable (touched 1, empty_total 3): the emptiest span alone holds 61 holes, more than the 24 follow-ons, so every policy's burst lands in one span and the two untouched spans plus the sweep account for the same empties. At class 256 they separate, AGAINST best-fit: holes per span at the fragmented point are 14 / 7 / 13 (ranks 0/1/2). Current and first-fit touch 2 spans and leave 2 spans empty after the originals are freed; best-fit touches 3 and leaves 1. The mechanism is visible in the numbers: tightest-first consumes the small holes first (7, then 13), still owes 4 of the 24 follow-ons, and is forced into the emptiest span - so the span best-fit exists to spare is exactly the span it ends up occupying, while current/first-fit fill the emptiest span's neighbour first and never touch one whole span at all. First-fit equals current on every leg B metric (the active pointer and the list-order scan name the same serving span on this workload), which is itself a filed result: the active-span shortcut costs nothing measurable here.
Grades, in the roadmap's own terms: current vs first-fit TIE on every measured quantity; best-fit LOSS to current on the decision leg at class 256 (touched 3 vs 2, empty_total 1 vs 2) and TIE at class 256's f3class and at every class-64 metric. Pre-registered clauses (b) and (c) fail, so the decision needs no discretion: NO ADOPTION.
Cost note (not graded, no adoption bar rests on it): best-fit scans every span of every class in the global list on each selection, in both selection sites, where the current policy is O(1) on an active hit - a structural cost a future re-trial must price with a spans-scanned counter before it can argue adoption on any workload.
Re-open condition (named, not scheduled): a burst-size sweep (follow-on volumes that fit inside the tight holes, e.g. 4..16 at class 256) is the one regime this trial does not measure and the only one where best-fit's mechanism could plausibly win; any future placement slice must pre-register its burst sizes and decision rule the same way, and price the scan cost. Until such a run exists, D-009 stands.
