=== ROOT CAUSE OF THE FIRST RUN FAIL, AND THE FIX ===
The prior lead run (hidden_files/z085_run.log, 19:49 EST, exit 1) completed all six Python legs correctly but both Ollama legs returned the JSON error: model qwen2.5:0.5b not found, although ollama list on the host shows the model. Root cause, verified first-hand this session: the host ollama service is a systemd system service running as user ollama with a drop-in override Environment OLLAMA_MODELS=/mnt/vault/models/ollama (systemctl show ollama -p Environment). ollama list talks to that service on port 11434 and therefore sees the vault store. The runner started its private servers with only OLLAMA_HOST=127.0.0.1:11499 set, so they defaulted to the login user store ~/.ollama/models, which is empty (its manifests tree was created empty by those very server starts at 19:48-19:49). The model was never missing; the private servers were looking in a different store.
Fix (runner only, in scope): run_z085.sh now discovers the service OLLAMA_MODELS via systemctl show (fallback: /mnt/vault/models/ollama if present, else the per-user default), exports it, prints it, and passes OLLAMA_MODELS explicitly to both private-server legs; after readiness it fetches /api/tags into hidden_files/z085_reps/ollama_<mode>_tags.json and FAILs the leg if the model is not visible there. The vault store is world-readable and was only read: no model was pulled, deleted, or copied, and the user :11434 service was never stopped or reconfigured (one read-only generate against :11434 during diagnosis confirmed the host service healthy).
