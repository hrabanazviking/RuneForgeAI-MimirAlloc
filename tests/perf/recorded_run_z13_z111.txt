Findings: (1) Z-095's v1 reproduces in this window -
lifecycle -45.19% (Z-095: -45.29%) and the small_churn
regression direction (+4.62%; Z-095: +6.13%). (2) The
regression is carried by the BATCH, not the capacity:
batch 16 alone (wB) reproduces it (+4.77%) while buying
almost nothing on lifecycle (-2.03%); capacity 32 alone
(wA) keeps nearly all of v1's lifecycle win (-44.03%) with
NO churn regression (-0.80%). Mechanism, consistent with
the code: in one-live-block churn every refill/drain cycle
moves a full batch through the locked core, so doubling
the batch doubles that per-cycle take/return work, while
capacity only bounds how many already-freed blocks wait
locally. v2 was therefore designed batch-8 everywhere.
Cross-check: this window's v0 (churn 33.56, lifecycle
536.37) sits on top of Z-095's v0 (33.62, 538.44) - the
two windows are measuring the same machine state.
