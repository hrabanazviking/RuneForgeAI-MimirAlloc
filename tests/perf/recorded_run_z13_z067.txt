S2. Mechanism (src/core/mimir_core.c/.h)
span_live_audit_locked(): the per-span half of the J-006 integrity
  walk's span invariant, promoted to the release paths --
  free-list nodes (walked with span_free_node_valid, bounded by
  carve_count) + live_count + tls_binned_count_locked(span) must
  equal carve_count exactly. An OOL trial span is judged by its
  bitmap recount (ool_popcount_locked == live_count), exactly as
  the walk judges it. This is the smallest remedy named for
  INC-J006-06 in docs/PHASE_10_METADATA_INTEGRITY.md: verify on
  the cold release paths before trusting live_count == 0.
Consulted at exactly the whole-span release decisions:
  (a) trim_some_locked victim selection -- the shared walk behind
      mimir_core_drain_retained, mimir_core_trim_retained and
      mimir_core_trim_retained_some; a candidate that fails the
      audit is skipped, never released.
  (b) the retention-overflow release in small_free_locked (both
      the production and the MIMIR_DEBUG courses): the span is
      released only when the audit passes.
  (c) the TLS retention sweep (tls_retention_sweep_locked):
      the per-batch sweep that releases spans the bin drains
      just emptied, on the same live_count == 0 trust.
  (d) the tally free course (small_free_tally_locked): its
      retention-overflow release, on the same trust; reached
      only from mimir_core_free, which reports it (op free).
  Sites (c) and (d) were wired after the slice's reviewer
  pass named them: a scratch experiment on this host
  (/tmp/exp67d.c against the tree with only (a)+(b) wired)
  proved the gap was live -- a worker thread holding one
  live object with live_count corrupted to 0 lost its whole
  span to the thread-exit sweep (mincore: span unmapped
  under the live block). The sweep's refusals are reported
  by the draining entries: mimir_tls_cache_drain_thread
  and the tss thread-exit destructor report op trim after
  unlocking; sweep refusals inside a free entry report on
  that entry's op free. Leg "sweep" (S3) proves (c) end to
  end; (d) shares the audited condition shape and the free
  entry's reporting, and is covered by the same invariant
  (the S9 TLS-ACCT relation quoted at S2's head).
  The audit runs only on spans already selected as release
  candidates (live_count == 0, no TLS tally, retention exceeded
  or a trim/drain walk). Nothing on the alloc path and no
  non-emptying free pays for it.
On a proven mismatch the release is REFUSED: the span stays
  retained and mapped, its objects stay live, nothing is unmapped
  on a count nobody can trust (the F-06 posture, by analogy).
Tallies: Z-067 appends at the END of struct mimir_stats (the
  Z-064 append discipline), after the point where Z-064/Z-065/
  Z-066 append theirs in banking order (resolution pre-declared
  in S7):
    uint64_t live_release_detections;
    uint64_t live_release_collateral_refusals;
  plus lock-free getters mimir_core_live_release_detections() /
  mimir_core_live_release_collateral_refusals() (shape (b),
  bound local; nm -D stays exactly 4, S4). Episode semantics
  (the Z-066 pattern): the first refusal for a distinct
  (span, walked-nodes / live_count / carve_count) signature is
  one detection; repeats of the same signature are collateral;
  a later passing audit of the same span closes the episode.
Diag wiring (J-007 channel): ops appended DRAIN=4, TRIM=5
  (FREE=3 is Z-066's, carried identically on this branch so the
  enum and the name tables stay index-true; resolution in S7);
  cause METADATA=6 is shared with Z-066 (the identical line is
  carried here; keep one at banking). The locked audit tallies
  itself and sets a thread-local label; the entry point reports
  after unlocking (op free / drain / trim, cause metadata).
  Tallies are ungated; emission is env-gated exactly as the
  channel is (proven by the gate-off leg, S3).
Scope of the audit, stated plainly: it proves the count relation
  of the candidate span only. A corruption that PRESERVES the
  relation (live_count lowered while the free list grows by the
  same amount -- which needs a second, list, write) is outside
  it; the registry-wide live sum (walked live_count ==
  mimir_live_small_objects) stays the integrity walk's job.
  A candidate whose free list cannot be walked to a count
  (invalid node, or more nodes than carve_count) is refused
  and tallied under the same counters with a sentinel
  signature: the count relation is unproven either way.

S6. Class 3 -- INC-J006-04 undetectable-by-design record
The corruption: a span's free_head is repointed at an object of
  the same span that is still LIVE. The next allocation from
  that span's central list returns the live object: two owners,
  one extent (proven on this host: experiment + leg 5 + probe
  20 -- after a drain returns bin stock to the central list,
  overwriting the head with the live object's pointer makes the
  next mimir_malloc(32) return that very object; a write
  through one alias is read through the other).
Why no operational detection exists in this design:
  the free list is IN-BAND -- a free node's only mark is its
  position in the list, and a carved slot start is shape-valid
  as a node whether the slot is live or free (span_free_node_
  valid cannot distinguish them, and says so). Every count the
  allocator keeps is preserved by the corruption: the walked
  node count still equals carve_count - live_count - tally in
  the minimal shape (the J-006-era probe: list of one, carve ==
  live + 1 -- the integrity walk returns 0 there), because the
  corruption changes WHICH slot the list names, never HOW MANY.
  There is no liveness record outside the 96-byte header in
  this design for a pop-time check to consult. Detection
  therefore requires new state, not new wiring.
What the walk does see here: in the populated-list shape built
  on this host (7 central nodes after the drain), replacing the
  head truncates the walkable list, so mimir_core_metadata_
  check() reports 1 violation (the node count). That is
  incidental -- it vanishes in the minimal shape -- and in any
  case no operational path consults the walk. It is recorded
  as an observation, not claimed as a control.
Compensating controls (what stands instead, today):
  1. Shape validation refuses wild, misaligned and
     out-of-carve heads outright (span-freehead-wild is a
     DETECTED class): the corruption must name an exact carved
     slot start of the same span to have any effect at all.
  2. Bounded blast radius: the overlap is exactly one object
     of one size class in one span, and the allocator's own
     accounting stays consistent through the handout
     (live_count and the live-object total increment normally;
     the two eventual frees decrement them back).
  3. The class stays exercised: probe 20 runs in the suite in
     its host-true shape and Z-068's full 25-probe re-run
     re-derives this verdict on the merged tree.
  4. The designated fix road is costed where the roadmap put
     it: a per-span liveness record (bitmap / freelist
     membership) is the subject of Z-069 (canary economics)
     and Z-070 (double-free detection economics -- freed-block
     poison + freelist membership), which own the adopt/reject
     decision by measurement. If membership state is adopted
     there, a pop-time liveness check becomes possible and
     this class should be re-opened.
  5. In MIMIR_DEBUG builds the J-005 quarantine holds freed
     blocks out of reuse entirely, which narrows the window
     in that flavour (no claim is made for production builds).
