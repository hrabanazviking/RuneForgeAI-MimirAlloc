S2. Mechanism (src/core/mimir_core.c/.h, +294/+37)
One size_t budget scalar under the global lock (0 =
unset, the default); _Alignas(64) atomic
Q-REFUSED-BUDGET tally; thread-local refusal flag (the
Z-066 label discipline). budget_admit_locked judges
projected = Q-MAPPED + new_length (overflow-saturated,
equality admitted) under the lock at the four growth
points: fresh large mapping (alloc_locked, on the pool
probe's checked round-up; pool hits never reach the
gate), fresh aligned mapping (alloc_aligned_locked),
fresh span (span_acquire_locked, one page + the Z-034
side page under MIMIR_OOL_META; reclaim step skipped
under MIMIR_LOCK_SHARD by shard discipline), mremap
growth (grow_mremap_locked, delta only, refusal
unconsumed so the fallback move re-judges and counts
exactly once). Over budget: trim_some_locked releases
retained EMPTY spans one at a time with re-judging,
then the pool is released whole and re-judged once;
still over, refuse. Entry points consume the flag
after unlocking and count exactly one refusal per
refused call: alloc, calloc, aligned_alloc (+ posix
through it), realloc (both grow courses), reallocarray
(through realloc), and the TLS refill course inside
tls_alloc. Snapshot pair budget_failures /
budget_mapped_bytes appended at the END of struct
mimir_stats; lock-free getter mimir_core_budget_failures;
setter/getter pair mimir_budget_set/get_mapped_bytes
(G-007 posture: -2 / (size_t)-1 on lock failure;
setting performs no release).

baseline value itself, which measured 0 on this host,
and 0 is the unset sentinel: the request was admitted

page (below the pooled total, still refusing the

pool (reclaimable 16384 B >= request 12288 B): it was
correctly admitted -- reclaim-before-refusal is the
design, not a defect. Fixed: the leg now requests
65536 bytes, beyond budget + all reclaimable bytes.
