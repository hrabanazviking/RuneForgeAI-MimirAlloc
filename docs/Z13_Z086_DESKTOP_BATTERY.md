# Z-086 - Desktop battery

Roadmap slice Z-086: KDE application battery (kcalc /
kwrite-class apps and a plasmashell component where
safely testable) under preload in a contained session;
rollback is unsetting one environment variable.
Gate: battery report with the containment method stated.

This doc is the battery report. The machine evidence is
tests/abi/recorded_run_z13_z086.txt (generated by
tests/abi/run_z086.sh, standalone via `make test-z086`):
RESULT PASS, zero FAIL lines. Per-application logs are
filed in hidden_files/z086_<app>_<mode>.log. The preload
is the Z-082 interposing variant as banked
(build/libmimiralloc_interpose.so, exactly 20 exports,
re-proven in the run S1; the Z-082 suite is re-run green
as neighbour evidence in S2, PRELOAD-VERDICT: MIMIR).

## S1 Containment method (stated, as the gate requires)

purpleraider is a live desktop host: at battery time the
owner session ran plasmashell PID 19610 and kwin_wayland
PID 19417 on wayland-0 / X display :0. Nothing was
preloaded into, attached to, or signalled in that
session. Every application in the battery ran in a
contained session built only for the run:

- a private throwaway HOME, XDG_RUNTIME_DIR,
  XDG_CONFIG_HOME, XDG_DATA_HOME and XDG_CACHE_HOME
  under one mktemp root, deleted at teardown;
- its own dbus-run-session: a private session bus
  created per run and destroyed with it;
- QT_QPA_PLATFORM=offscreen, the headless Qt platform:
  no display connection is ever opened; DISPLAY,
  WAYLAND_DISPLAY and SESSION_MANAGER are unset;
- its own setsid process group, terminated at the end
  of the observation window (8 s, 10 s for
  plasmashell); leftover processes are swept by an
  environment marker (the private XDG_RUNTIME_DIR),
  never by process name, so a same-named live process
  can never be signalled by mistake.

Why this road: Xvfb is not installed on this host, and
Xephyr (present) needs a parent display - the only
parent display is the owner live session, which is out
of bounds. The headless Qt platform plus a private bus
is a fully contained session that touches no part of
the running desktop. Proof filed in the run S6: the
live plasmashell and kwin_wayland PID sets are byte-
identical before and after the battery, and the
containment root is deleted.

## S2 Battery results (control vs preload, same session)

Every row ran twice in identical containment: control
(glibc, no preload) and preload (LD_PRELOAD of the
Z-082 variant). ALIVE means the application held its
event loop for the whole window and was then terminated
by the runner (timeout rc 124); EXITED-CLEAN means it
finished startup and exited 0 inside the window.

| app | control | preload | verdict |
| --- | --- | --- | --- |
| kcalc | ALIVE | ALIVE | PASS |
| kate (kwrite-class) | EXITED-CLEAN | EXITED-CLEAN | PASS |
| dolphin | ALIVE | ALIVE | PASS |
| gwenview | ALIVE | ALIVE | PASS |
| okular | ALIVE | ALIVE | PASS |
| plasmawindowed + org.kde.plasma.digitalclock (plasmashell component) | ALIVE | ALIVE | PASS |
| plasmashell --no-respawn | FAILED rc 139 | FAILED rc 139 | ENV-ONLY, see S3 |
| kwrite | - | - | MISSING-APP, see S3 |

Rollback (run S5): kcalc run again in the same
containment with LD_PRELOAD unset is ALIVE on glibc -
rollback is unsetting the one environment variable,
as the roadmap states.

## S3 Triage - every non-pass named to its cause

- kwrite: MISSING-APP. No /usr/bin/kwrite exists on
  this host. The kwrite-class row is carried by kate
  (same KTextEditor family), which passes.
- plasmashell (full shell): ENV-ONLY, and as allocator
  evidence NOT TESTED. The shell segfaults identically
  with and without the preload (rc 139, KCrash as the
  only output in both logs): it requires a live
  Wayland/X compositor session, and the contained
  headless session has none by design. A crash that is
  byte-identical on the glibc control is not an
  allocator result and is never counted as one. The
  safely testable plasmashell component - the
  plasmawindowed shell-component runner hosting the
  org.kde.plasma.digitalclock applet - was tested and
  passes under preload.
- Containment noise, present in control and preload
  logs alike, not failures: the offscreen plugin notice
  in every Qt row; the private-bus ActivityManager
  activation failing with signal 6 in BOTH
  plasmawindowed runs (kactivitymanagerd cannot run
  headless) while plasmawindowed itself stays ALIVE;
  dolphin session-restore and clipboard notices;
  gwenview QPainter notices under the offscreen
  painter. All are properties of the headless
  containment, identical on glibc.

## S4 Boundaries of this result

- The offscreen platform exercises Qt startup, plugin
  loading, KIO, document and image machinery and the
  allocation behaviour of all of it under the variant;
  it does not exercise a real Wayland/X rendering path
  or GPU buffers. That is the honest reach of a
  contained session on a live host.
- No allocator defect was found: no row fails under
  preload while passing on the control. Machine load
  was quiet throughout (0.54-0.64) and no benchmark
  numbers are claimed by this slice, so no load-
  sensitive verdict exists here.
