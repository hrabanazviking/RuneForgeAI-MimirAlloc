## 2. Why a compiled binary (attempt-1 finding)

Attempt 1 ran the engine via `mojo run` (preserved in
hidden_files/z087_recorded_run_attempt1.txt and
hidden_files/z087_mojorun_preload_episode.log). Under
preload, the process being interposed is then the Mojo
COMPILER: its compile-time allocation churn under the
interposer did not finish within a 600 s bound (100%
CPU, RSS ~215 MB, still compiling), while the plain
mojo-run leg completed in 20.14 s wall (decode_ms
4368.047 for 32 tokens). The token path is therefore
trialled on the compiled binary, which is also the
only place the token path exists in isolation. The
600 s non-completion is recorded as an observation
about compiler-in-process preload, NOT as an Aesir
defect and NOT as an allocator defect: no leg of
attempt 1 produced a wrong result; the preloaded
compile simply did not finish inside the bound.

| decode_ms           | 3797.493, 4127.256  | 4162.274, 4263.026  | +6.3% |

| minor page faults   | 978739, 979649      | 1117035, 1117095    | +14.1% |

Reading, plainly:

- CORRECTNESS: TIE. The interposer changes no output:
  identical token stream and identical response text
  in every leg, plain and preloaded, both reps.
- PERFORMANCE: a small, consistent LOSS under preload
  on this run -- the preloaded legs were slower on
  wall and decode in BOTH reps, with ~14% more minor
  page faults and unchanged RSS. Because the host was
  under cross-campaign load throughout (loadavg up to
  4.43), this is recorded as a measured-under-
  contention observation in the roadmap's grades, not
  as a baseline: LOSS (this run, contended host). A
  quiet-machine re-run is the honest road to a
  baseline grade; none is claimed here.
- The prefill and load phases show no consistent
  preload effect (deltas inside rep-to-rep noise);
  the cost, where it appears, sits in decode -- the
  allocation-dense phase -- which is the expected
  signature of interposition overhead, and its size
  here is single-digit percent.

## 5. Aesir-side blockers, named not fixed

Per the gate, each of these is an Aesir-side fact
found by read-only recon; none is fixed in this repo
and none blocks the trial, which routes around all
three via the canonical source build:

- B-087-1: the prebuilt root aesir_main in the Aesir
  tree (2026-11-11 build) loads the fixture GGUF and
  then SEGFAULTS in prefill on a PLAIN run (no preload
  involved). A stale-binary defect on the Aesir side;
  the source build of record does not show it.
- B-087-2: aesir_engine/aesir_main in the Aesir tree
  is an older stub that returns canned text rather
  than genuine generation; it is not the token path
  of record and was not used.
- B-087-3: aesir_engine/model.gguf in the Aesir tree
  is a 24-byte empty header, not a model. The fixture
  of record is hidden_files/fixtures/Meta-Llama-3.1-
  8B-Instruct-Q4_K_M.gguf (identity in S0 above).
