# Z13 The Interposing Variant (Z-082)

Roadmap slice Z-082 (Wave 10 opener, L-01's opt-in
route): an opt-in build whose library interposes the
malloc family; symbol-table audit against glibc's set,
every missing symbol a named list entry, never a
surprise at runtime. The recorded decision is D-015 in
docs/DECISION_LEDGER.md; the machine evidence is
tests/abi/recorded_run_z13_z082.txt (generated by
tests/abi/run_z082.sh: PASS, zero FAIL lines). Gate
(roadmap, verbatim): interposing .so builds; symbol
diff filed. Both halves are met -- the .so builds
(S1/S3) and the diff is S4 of the recorded run, stated
in human form as S4 of this document.

## 0. Position and honesty notes

- Before this slice the library exported exactly ten
  namespaced mimir_* symbols and no standard name:
  adopting MimirAlloc meant rewriting call sites, and
  limitation L-01 recorded that no artifact replaced
  the system malloc family. D-012 (Z-075) expressly
  reserved the standard names -- malloc_usable_size
  named in the decision -- to "the Wave 10 opt-in
  variant's business". This slice is that variant.
- The variant is a SEPARATE library,
  build/libmimiralloc_interpose.so. It is never built
  by `make lib`, `make all` or `make test`; it is built
  only by the explicit `make lib-interpose` (or as a
  dependency of `make test-z082` / the recorded run).
  The default libmimiralloc.so is byte-for-byte the
  Z-078 build contract: exactly ten namespaced exports,
  and the recorded run's S2 proves mechanically that
  NONE of the ten standard names appears in it.
  Interposition is therefore never a surprise from the
  default build; L-01 stands, now with its opt-in route
  built. L-01's own text is not edited by this slice --
  the register's next revision owns its wording.
- What this slice does NOT do, by roadmap design:
  memalign/valloc/pvalloc shims and the strdup-class
  assessment are Z-083's assignment; the LD_PRELOAD
  smoke battery over real programs is Z-084; workload,
  desktop and Aesir trials are Z-085..Z-087; the
  never-preload packet is Z-089; the Wave 10 verdict is
  Z-090. This slice files ONE contained preload proof
  (S5 below) -- the minimum needed to prove the .so
  actually interposes at runtime, not merely that it
  builds -- and claims nothing about real programs.
- The public header include/mimir_alloc.h is NOT
  changed: the variant adds no namespaced declaration,
  and the header's existing sentence (standard-name
  interposition is the Wave 10 variant's business)
  pointed here all along. The interposed names are
  declared by the system headers of any consumer, and
  locally in src/api/mimir_interpose.c.

## 1. The build

- src/api/mimir_interpose.c -- one new translation
  unit defining exactly ten standard names, each a pure
  forwarder to the L1 namespaced entry of the same
  shape in src/api/mimir_alloc.c. No logic of its own:
  no size arithmetic, no errno handling, no fallback.
  Calls therefore pass through the L1 boundary (the
  E-005 audit counters move; S3 of the test plan) --
  there is no back door around the audit surface.
- src/api/mimir_interpose.map -- the variant's own
  version script (anonymous node, the E-002 reasons):
  exactly twenty exports, the ten namespaced names (so
  both surfaces in one process are the SAME allocator
  instance, never two) plus the ten standard names;
  local: * binds everything else, audit counters
  included. The standard names are exported
  UNVERSIONED (glibc's are GLIBC_2.x-versioned): a
  consumer binds by name at load time, which is the
  interposition mechanism itself -- and one more reason
  the variant is opt-in only.
- The interpose object and every Z-082 test object are
  compiled -fno-builtin, so no builtin malloc-family
  assumption can rewrite an interposed definition or
  fold a probe (the preload probe's malloc(0) test
  would otherwise be a fold candidate).
- Recursion safety, by inspection at this slice:
  src/core and src/platform call no public malloc-
  family name -- the allocator consumes the OS only
  through its L6 wrappers (mmap/munmap and kin) and the
  C11 thread/TSS machinery -- so an interposed call can
  never re-enter the variant through the allocator's
  own work. The TLS cache's first touch needs no
  allocation (zero-initialised static _Thread_local
  storage IS the empty cache; registration is call_once
  + tss_set), which is what makes early-runtime
  (pre-main, library-init) interposed calls survivable;
  the S5 preload proof exercises exactly that path,
  because the dynamic loader and libc init run before
  the probe's main.

## 2. The interposed set

| Standard name | Forwards to | Note |
|---|---|---|
| malloc | mimir_malloc | |
| free | mimir_free | free(NULL) stays the defined no-op |
| cfree | mimir_free | glibc's legacy alias of free (same address in libc.so.6, S4 raw rows); the alias carries no distinct semantics |
| calloc | mimir_calloc | requested extent zeroed, as before |
| realloc | mimir_realloc | D-013 divergence, S3 below |
| reallocarray | mimir_reallocarray | checked product, as before |

| posix_memalign | mimir_posix_memalign | return value is the error channel |

| malloc_trim | mimir_trim | same 1/0 return shape as glibc's |

## 3. Inherited divergences (D-013 under standard names)

Interposition changes the NAMES, not the contract.
Every D-013 answer is inherited exactly, and each is
pinned through the standard names by
tests/abi/test_z082.c S3 and the dynamic consumer:

| Call | This variant | glibc on this host |
|---|---|---|
| malloc(0) | NULL (posture-counted refusal) | distinct freeable pointer per call |
| calloc(0, n) / (n, 0) | NULL | non-null pointer |
| realloc(p, 0), live p | NULL, p LIVE, intact, caller-owned | NULL, p freed |
| reallocarray zero factor | NULL, original preserved | NULL, original freed (via realloc) |
| posix_memalign(valid, 0) | ENOMEM, *memptr unchanged | 0, *memptr set |
| allocation failure | NULL, errno untouched on checked refusals | NULL, errno = ENOMEM |

The realloc(p, 0) row is the sharpest edge and is
stated plainly: a program that relies on the glibc
reading (realloc-to-zero as a free) LEAKS the block
under this variant. It is never corrupted, never
double-owned, and still freeable by the caller -- but
the leak is real, it is a consequence of the uniform
realloc-NULL contract D-013 chose, and Z-090's verdict
must restate it for preload users. The zero-size rows
cut the other way for many real programs (a malloc(0)
result is never dereferenced legitimately), but they
are divergences all the same and are named here, not
discovered later.

A second standing hazard of ANY interposition, stated
for this variant: ownership is per-allocator. A pointer
obtained from glibc (strdup, getline, realpath and
kin -- functions whose results are malloc'd inside
libc, bound to __libc_malloc, which no preload can
replace) must never be freed through this variant's
free, and a variant pointer must never be freed by a
non-interposed free. Mixing the two in one call is
undefined behaviour with no defined error -- the same
family boundary the namespaced surface has always had
(the public header's foreign-pointer clause), now
reachable through standard names. Z-083's doc duty
(libc-internal users cannot be interposed) starts from
exactly this fact.

## 4. The symbol audit (the filed diff)

Basis: the defined dynamic symbols of this host's
/lib/x86_64-linux-gnu/libc.so.6 (glibc 2.44-1ubuntu2),
extracted mechanically at run time by run_z082.sh S4.
43 malloc-family symbols are present on this host.
Every one carries a disposition below; the run FAILS
if a family symbol appears with no disposition, so a
future glibc's new symbol becomes a loud audit event,
never a runtime surprise. Dispositions:

INTERPOSED (10) -- S2 table above: malloc, free,
cfree, calloc, realloc, reallocarray, aligned_alloc,
posix_memalign, malloc_usable_size, malloc_trim.

MISSING-NAMED (18) -- absent from the interposing .so,
each with its reason:
- memalign, valloc, pvalloc -- the explicit-alignment
  family over Z-074. THE ROADMAP'S Z-083 ASSIGNMENT
  ("memalign/valloc/pvalloc family over Z-074"),
  named there as this wave's next slice; absent here
  by design, not by oversight.
- mallopt, mallinfo, mallinfo2, malloc_info,
  malloc_stats -- glibc's introspection/tuning class.
  Their types are glibc heap shapes (struct mallinfo's
  arena fields describe a main-arena allocator this
  core is not); mimir_stats_snapshot is the honest
  counterpart and it is namespaced-only with its own
  versioned struct. Returning glibc-shaped structs
  filled with translated numbers would claim a heap
  geometry that does not exist. Named gap; no owner
  slice yet -- a candidate for the Wave 10 verdict
  (Z-090) to assign or to close as wontfix.
- mcheck, mcheck_pedantic, mcheck_check_all, mprobe,
  mallwatch, mtrace, muntrace -- glibc's debug-aid
  class, defined against glibc heap internals and the
  __malloc_hook mechanism (inert since glibc 2.34).
  This allocator's integrity story is its own Wave 8
  diagnostics channel, not a mcheck emulation. Named
  gap; same Z-090 disposition question.
- memalignment -- new in GLIBC_2.43: the alignment
  query for a live block. No namespaced counterpart
  exists (D-012 defined a usable-size query, not an
  alignment query). Named gap; the natural owner is a
  future namespaced-surface slice, after which this
  variant gains the standard name by the S2 rule.
- free_sized, free_aligned_sized -- new in GLIBC_2.43
  (the C23 sized-deallocation pair). A sized free that
  ignored its size argument would claim a check it
  does not perform; an honest one validates against
  the D-012 usable extent. Named gap; candidate owner
  a future slice pairing both names with that
  validation, or Z-090's wontfix list.

INTERNAL (15) -- present in glibc, correctly absent
here, and NOT gaps: __libc_malloc, __libc_free,
__libc_calloc, __libc_realloc, __libc_reallocarray,
__libc_memalign, __libc_valloc, __libc_pvalloc,
__libc_mallinfo, __libc_mallopt (the libc-private
aliases glibc binds its own internal calls to --
interposition cannot reach them by construction, and
defining them in a preload library would claim
otherwise), and __malloc_hook, __free_hook,
__realloc_hook, __memalign_hook,
__malloc_initialize_hook (data objects of the hook
mechanism glibc itself stopped calling in 2.34;
providing them would resurrect a dead promise).

Version evidence (S4 raw rows): the family's public
names are GLIBC_2.2.5-versioned except reallocarray
(2.26), mallinfo2 (2.33), malloc_info (2.10),
aligned_alloc (2.16) and the GLIBC_2.43 trio
(memalignment, free_sized, free_aligned_sized);
cfree is a compat (single-@) symbol at free's address;
the __libc_reallocarray alias is GLIBC_PRIVATE.
