# Z13 LD_PRELOAD Smoke Battery (Z-084)

Roadmap slice Z-084 (Wave 10): LD_PRELOAD smoke battery
-- coreutils, git, python3, bash and the repo's own test
binaries under preload on the seat host; per-program
pass/fail with logs. Gate (roadmap, verbatim): battery
report; every failure triaged to a named cause. Both
halves are met: the battery report is
tests/abi/recorded_run_z13_z084.txt (generated by
tests/abi/run_z084.sh: PASS, 74 [ok] lines, zero [FAIL]
lines), and the one failure the battery found is triaged
to a named cause at S3 of this document (T-084-1) and
pinned as an asserted expectation in S9 of the recorded
run -- not hidden, not waived, and not an allocator
defect (it is the D-013 contract behaving as decided).

## 0. Position and honesty notes

- Preload target is exactly the Z-082 interposing
  variant, build/libmimiralloc_interpose.so, as banked
  (20 defined dynamic symbols: 10 namespaced mimir_*
  + 10 standard names; re-proven in S1 of the recorded
  run on this tree, which includes banked Z-083 --
  Z-083 extended the DEFAULT library only and did not
  change the interposing variant's export set).
- A program is counted as a preload PASS only when the
  interposition is PROVEN for that program, never from
  a clean exit alone: (a) LD_DEBUG=files loader output
  for the program's own preloaded leg names
  libmimiralloc_interpose.so; (b) the preloaded leg
  exits 0; (c) its stdout is byte-identical to a plain
  (glibc) control leg run immediately before it, same
  argv/cwd/input. The mechanism itself is proven by
  the Z-082 probe pair (S2: plain GLIBC / preloaded
  MIMIR) plus a negative control (a bogus preload path
  must produce a loader "cannot be preloaded" error,
  proving the harness notices non-loading).
- The repo's own test binaries are LIBOBJS-direct-
  linked for their mimir_* calls (their linkage lines
  are filed in S7 of the recorded run). For them the
  preload coverage is honestly scoped: their libc
  malloc-family calls are interposed and the two
  allocator instances (direct-linked + preloaded)
  coexist in one process -- the double-instance risk
  is the thing being smoked, and all eight passed both
  legs with identical output.
- Host load state is recorded in the recorded run
  header and per-program logs (loadavg 0.23 at battery
  start, 1.75 at end on 32 threads -- a shared machine;
  this battery asserts functional behaviour only, no
  timing numbers are claimed anywhere in this slice).

## 1. The battery

Runner: tests/abi/run_z084.sh. Per-program full logs:
hidden_files/z084_<program>.log (plain rc, preloaded
rc, preloaded stdout/stderr, load state). Subjects and
smoke commands (all deterministic, read-only or
temp-dir only, 120 s timeout per leg):

- coreutils (S3): sort -n + sort -k2 -n | tail over a
  generated 20000-line file, sha256sum, wc -l,
  ls /usr/bin | sha256sum, cat | grep -c '500'.
- git (S4): log --oneline -20, rev-parse HEAD,
  status --porcelain | wc -l, ls-files | wc -l, all
  against this repo, read-only.
- python3 (S5): 2000 x bytearray(4096) churn, a
  5000-entry dict of lists, a sha256 over block
  prefixes and a full sum -- one printed digest set.
- bash (S6): 2000-element indexed array with
  arithmetic accumulation, five subshell pipelines
  (seq | paste | bc), printed sums.
- repo test binaries (S7): test_smoke, test_core,
  test_b007, test_c005, test_c006, test_c007,
  test_c008, test_d004 -- each run individually, both
  legs; a binary fails on a non-zero exit, a stdout
  divergence (waived only for test_d004's thread
  interleaving, which is not compared), or its own
  RESULT: FAIL line.
- probe binary as subject (S8): test_z082_pre, with
  the equality leg inverted by design -- preloaded
  stdout MUST differ (MIMIR verdict) from plain
  (GLIBC verdict); identity would mean non-loading.

## 2. Results

All 13 subjects PASS in the final recorded run:
coreutils, git, python3, bash, the eight repo
binaries, and the probe binary -- each with the .so
proven loaded, both legs exit 0, stdout parity (or
the probe's asserted divergence). Totals reconcile:
13 subjects, 13 pass, 0 fail, 0 skip; 74 [ok] lines,
0 [FAIL] lines in the recorded run.
